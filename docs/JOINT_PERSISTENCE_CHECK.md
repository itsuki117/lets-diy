# joint の自動保存・起動時復元の回帰検査

2026-10-19、Qiita のコメントで提案された保存前後の比較を、既存の Vitest に追加した。

## 再実行

```sh
npm test -- src/ui/__tests__/jointPersistence.test.tsx
```

実装は `src/ui/__tests__/jointPersistence.test.tsx`。2 ケースを検査する。

- joint の名前と有効・無効だけを Transient で変更し、確定・自動保存・起動時復元を経ても保持する。
- 実際の joint 更新コマンドで移動量だけを 0 → 50mm に変更する。確定・自動保存までは 50mm を保持し、起動時復元では設計仕様に従って 0 に戻る。

実際の部材・金物追加コマンドで、板 2 枚、丸穴加工、リニアガイド、ガススプリングを用意する。最初の自動保存を確認した後に joint だけを変更する。保存・読込・ライフサイクル処理はモック化しない。

保存完了は固定 sleep で判断しない。Vitest の仮想タイマーで実際の予約済み debounce を実行し、`localStorage` の保存内容と、保存成功コールバックで更新される `savedProject` の両方を確認する。保存対象の `Project` 全体を比較するため、`parts` 内の加工、`joints`、`hardware`、`gasSprings` の値や関連 ID の欠落も検出できる。

その後、ライフサイクルをアンマウントし、メモリ上のプロジェクトを空にしてから再マウントする。起動時の復元確認を承諾し、保存データだけから復元した結果を比較する。再読込直前の `beforeunload` 保存で、失敗した自動保存が補われることはない。

## 読込時に意図的に変わる値

`src/core/project/serialize.ts` の `fromDocument()` と `docs/DESIGN_V2.md` §9.6 は、読み込み時に可動量を 0、ドアロック・ガススプリングのロックを解除状態へ戻す。今回の fixture ではガススプリングに `locked: false` が明示される点も期待値に含め、それ以外の値は全体比較する。期待値は読込関数から生成せず、テスト側で明記している。

したがって、コメントにある「joint 値が再読込後も同じ」を移動量・角度の完全一致と解釈すると、現在の仕様とは一致しない。名前などの設定の保持と、動作状態の初期化を区別する。アプリの保存仕様は変更していない。
