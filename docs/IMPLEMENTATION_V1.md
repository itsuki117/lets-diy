## 既知の事項・設計からの意図的な逸脱

### 1. 選択アウトラインをバウンディングボックスに変更した

**設計書 §3.6 / §9.2**: 加工後メッシュの `EdgesGeometry` で輪郭を描く想定だった。

**実装**: 部材の現在のバウンディングボックスの枠（常に 12 本）を描く。

**理由**: CSG の出力には T 字接合（辺の途中に他の三角形の頂点が乗る）が避けられない。
頂点を位置だけで統合しても、T 字接合の辺は 2 枚の三角形に共有されないため `EdgesGeometry` が拾ってしまい、
面の中に分割線が残って見た目が汚くなる（実測 70 本）。
バウンディングボックス方式なら常に 12 本で、切断すれば枠も縮む。穴や切り欠きの形までは追わないが、
「どれを選んでいるか」「どこを占めているか」を伝えるという目的には足りる。
形に沿った輪郭が必要になったら Ver.2 で検討する。

### 2. 穴の位置入力は面内の 2 軸だけ表示する

**設計書 §3.4**: X / Y / Z の 3 つを表示するモックだった。

**実装**: 方向軸に直交する 2 軸だけ表示する。

**理由**: 方向軸の成分は「どの面から掘るか」で決まるため `toolSolidSpec` が上書きする。
無視される値を入力させるとユーザーが混乱する。切り欠きは 3 軸すべて表示する。

### 3. 切断プレビューは表示用に部材範囲へ切り詰める

**設計書 §13.1 / §13.5**: プレビューと CSG はどちらも `toolSolidSpec` の 1 本を使う。

**実装**: 原則はそのまま。ただし切断だけは、表示専用の `previewSolidSpec` で部材の範囲に切り詰める。

**理由**: 切断のツール立体は「残さない側の半空間を覆う巨大ボックス」なので、そのまま描くと
画面が赤一色になって何が削られるのか分からない。CSG に渡すのは常に `toolSolidSpec` の方であり、
形状の真実は 1 本のまま保たれている。`previewSolidSpec` は切断以外では `toolSolidSpec` をそのまま返す
（`toolSolid.test.ts` で検証）。

### 4. `three-bvh-csg` の非推奨警告（上流の問題）

初回の CSG 実行時にコンソールへ 2 行出る:

```
MeshBVH: "maxLeafTris" option has been deprecated. Use "targetLeafSize", instead.
```

`three-bvh-csg` 0.0.18 が `three-mesh-bvh` 0.9.x に旧オプション名を渡しているため。
アプリ側から抑止できない。動作には影響しない。

対応の選択肢: 上流の修正を待つ / `CsgEngine` の実装を manifold-3d に差し替える（インターフェースを切ってあるので差し替えは容易）。

### 5. Ver.1 スコープとして実装していないもの

- 名前付きプロジェクトスロットの UI（`ProjectRepository` と localStorage 実装はあるが、「一覧から開く」画面は未作成。現状はファイル入出力 + 自動保存 1 枠）
- 複数選択時の移動 / 回転ギズモ（設計どおり単一選択のみ）
- 性能計測（部材 50 枚・加工 200 件のサンプル生成スクリプトと `docs/PERF_V1.md`）
- `README.md` への操作説明の追記

## 追加実装: アーチ切り欠き（Claude Code / 2026-09-22、ユーザー要望）

「切り欠きでアーチ状にできるとバリエーションが増える」という要望を受けて、
5 つ目の加工種類として `type: 'arch'` を追加した。

### 仕様

矩形の上辺を弧にした断面を、`direction` 軸方向へ押し出して削る。パラメータは 3 つ:

| 値 | 意味 |
|----|------|
| `width` | 開口の幅 |
| `height` | 断面の全高（弧の部分を含む） |
| `rise` | 弧の高さ。`0` で矩形、`width / 2` で半円、それ以外は楕円弧 |

`rise` を独立させたのは、家具でよくある「幅広で浅いアーチ」を作れるようにするため。
半円に固定すると 400mm 幅のアーチは必ず 200mm の高さになってしまい、実用範囲が狭い。
UI には［半円にする］［角にする］のショートカットを置いた。

### 実装上のポイント

- 断面は `THREE.Shape` + `absellipse`、立体は `ExtrudeGeometry`。
  素材そのものは直方体のままで、削る側にだけ曲線を持たせるので CSG は安定する。
  実測で 6 方向すべて、および丸穴との重ね掛けで失敗ゼロ。
- `ToolSolidSpec` に `shape: 'arch'` と `rise?` を追加した。
  `cylinder` と同じく **ツール自身の座標系**での寸法で、部材ローカルへの向き合わせは `rotation` が担う。
- 姿勢は「面内 2 軸を列ベクトルにした基底行列」＋「方向軸まわりのスピン」。
  `axis === 'y'` のときだけ左手系になるので幅の向きを反転して右手系に直している
  （断面は左右対称なので見た目は変わらない）。鏡像バグの回帰テストとして
  `arch.test.ts` で行列式が +1 になることを固定した。
- **検証はアーチ専用にした**。アーチは部材の端をまたいで削るのが普通の使い方なので、
  矩形の穴で使っている「端をはみ出しています」警告をそのまま流用すると、
  既定値ですら警告が出てしまう。代わりに「部材と重なっていない」「弧の上に材が
  10mm 未満しか残らない」の 2 つだけを見る。断面を回してある場合は上下が
  入れ替わるので、残り材の判定は弧が上を向いているとき（回転が ±30 度以内）だけ行う。

### schemaVersion を 1 から 2 へ上げた

加工データの変換は不要なので `MIGRATIONS[1]` は恒等変換だが、版を上げることで
「v2 のファイルを古いビルドで開くと『新しいバージョンで作成されています』と出る」
正しい挙動になる。migrate の仕組みを実際に使う最初の例でもある。

### テスト

- `src/core/__tests__/arch.test.ts`（28 件）— 寸法・姿勢・rise のクランプ・検証・ラベル・ハッシュ
- `src/geometry/__tests__/archGeometry.test.ts`（9 件）— 外接箱・半円の弧上の点・6 方向の CSG・丸穴との重ね掛け
- `migrate.test.ts` に v1 -> v2、`serialize.test.ts` の往復にアーチを追加

## 追加実装: 加工位置の 3 つの指定手段（Claude Code / 2026-09-22、ユーザー要望）

「加工が少しやりづらい。直感的にマウスで動かせると最高」への対応として、
まずドラッグとクリック配置を入れた。その後ユーザーが
「ドラッグと微調整用のボタン、それから座標入力の 3 つを採用」と指定したため、
**クリック配置を撤去して 3 手段に整理した**。仕様は設計書 §13.4.1。

### 入れたもの（粗い→細かいの順）

| # | 手段 | きざみ |
|---|------|--------|
| 1 | ギズモの矢印をドラッグ | グリッドスナップ（1/5/10mm、OFF可） |
| 2 | 微調整ボタン（− / +） | 0.5 / 1 / 5 / 10mm から選ぶ |
| 3 | 座標入力 | 自由（0.1mm まで） |

ドラッグと微調整ボタンは `core/operation/operationDrag.ts` の同じ純粋関数を通るので、
どちらで動かしても結果が一致する。下書きはエディタ状態なので履歴には積まれず、
確定するまで CSG も走らない。

### クリック配置を外した理由

部材を選ぶ・眺めるつもりのクリックで加工が飛んでしまう。しかも下書きは履歴に積まないので
Undo で戻せない。粗い位置決めはドラッグが担うため機能としても重複しており、
3 手段に絞ったほうが「どれを使えばいいか」が明確になる。

### 実装上のポイント

- **動かせる軸を種類ごとに絞った**。穴とアーチは掘る向きの軸を隠す（その成分は
  `toolSolidSpec` が上書きするので動かしても無意味）。切断は切る軸の 1 本だけ。
  切り欠きは 3 軸。ギズモの矢印も微調整ボタンの行も同じ判定（`draggableAxes`）で出し分けるので、
  「見えない軸は触れない」が一貫する。
- **ドラッグだけグリッドスナップを通す**。微調整ボタンと座標入力は通さない。
  3 つとも吸着させてしまうと、グリッドより細かく詰める手段がなくなる。
- ギズモは **部材と同じ姿勢を持つ group の子** に置き、`space="local"` で出す。
  部材が回転していても矢印が「板の縦・横」方向に出るので、斜めに置いた板でも迷わない。
- `draftHandlePosition` → `applyDraftPosition` の往復で Operation が変わらないことを
  全 5 種類でテストしている。ここが崩れると「ギズモを掴んだだけで加工がずれる」不具合になる。

### テスト

`src/core/__tests__/operationDrag.test.ts`（33 件）— 動かせる軸・ハンドル位置・
往復不変・切断のクランプ・6 方向・NaN 耐性、および微調整ボタンの刻み・
グリッドに吸着しないこと・± で元に戻ること。

### 実機確認

丸穴で 2 軸ギズモ（掘る向きの矢印が出ない）、切断で 1 軸ギズモを確認。
ドラッグは 10mm グリッドに吸着、微調整 0.5mm × 3 で +1.5mm、10mm × 2 で −20mm と
刻みどおりに動き、いずれも座標欄とリアルタイムで同期。
ドラッグ中にカメラが回らないことも確認済み。
