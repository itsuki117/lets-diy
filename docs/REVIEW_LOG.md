### Codex からの確認事項への回答

#### §12.4 の `gap` 符号（IMPLEMENTATION_V1.md 記載）

**指摘は正しい。設計書を修正した。**

`nB` は target の外向き法線であり、source は target の面の外側に接する。
目標平面は `pB + nB * gap` なので、

```
d = dot((pB + nB * gap) - pA, nB) = dot(pB - pA, nB) + gap
```

となり `+ gap` が正しい。DESIGN_V1 §12.4 手順 3 を修正済み。
`gap = 0` で密着、正値で隙間、負値でめり込む。Phase 5 のテストではこの符号で検証すること。

## 2026-09-22 — 角丸 / 部品表 / 干渉判定 と Ver.2 設計

ユーザー要望「角を丸くする処理」と、次のステップ（ヒンジ・スライドレール・ガススプリング・
動作シミュレーション・干渉判定・部品表生成）への対応。

### 実装したもの

| 機能 | 場所 |
|------|------|
| 角丸（6 つ目の加工種類 `roundCorner`） | `core/operation/toolSolid.ts` ほか。schemaVersion 3 |
| 部品表生成 + CSV 書き出し | `core/bom/`、`ui/bom/BomPanel.tsx` |
| 干渉判定（OBB 分離軸判定） | `core/collision/interference.ts`、`ui/bom/InterferencePanel.tsx` |

### 設計だけ書いたもの（未実装）

ヒンジ / スライドレール / ガススプリング / 動作シミュレーションは
[DESIGN_V2_MOTION.md](./DESIGN_V2_MOTION.md) と [PHASES_V2_MOTION.md](./PHASES_V2_MOTION.md) に
設計とフェーズ分割を書いた。実装はしていない。

**理由**: この 4 つは Ver.1 の一番深い前提（`Part.transform` が位置の唯一の真実）を壊す。
可動部材の姿勢は joint から計算される派生値になり、移動コマンド・ギズモ・Undo・保存・
干渉判定すべてに波及する。設計なしで書き始めると、
「扉だけギズモで動かすと壊れる」「保存したら角度が消える」といった直しにくい不具合が出る。
本リポジトリの分担（`CLAUDE.md`: 設計は Claude Code、実装は Codex）にも沿わせた。

### Codex への確認事項

| # | 内容 |
|---|------|
| A-08 | 角丸は**素材の外形**に対する加工。切断より後ろに置いても「切断後の新しい角」ではなく元の角を落とす。加工リストの並べ替えで調整する仕様（設計書 §13.2 に注記）。 |
| A-09 | `SCHEMA_VERSION` を 3 へ。v1 / v2 のファイルは恒等変換で読める。ユーザーのブラウザに残る自動保存を実機で 1 度確認してほしい。 |
| A-10 | 干渉判定は外形（切断を反映した OBB）のみ。穴の内側は見ない。面スナップの接触（食い込み 0.5mm 以下）は干渉としない。この 2 つは意図的な割り切りで、UI にも明記済み。 |
| A-11 | 部品表は「材質 + 形状ハッシュ」でまとめる。左右対称で穴位置が反転した部材は別行になるのが正しい挙動。 |
| A-12 | Ver.2 の実装に入るときは **Phase M1（運動学、UI なし）を必ず単独で切ること**。数式と描画を同時に書くと切り分けができなくなる。 |

### 実機で確認済み

角丸 R10 生成 -> R80 へ非破壊編集（四隅が丸くなることを目視）、
部品表（2 部材 / 1 種類 / 0.36 m2 と材料集計）、
干渉チェック（食い込み 18mm を検出し、該当部材が赤く表示される）。
